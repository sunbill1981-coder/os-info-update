## 验收证据

执行 `python3 -B -m unittest discover -s skills/windows-os-intelligence/tests`：217 项通过（原有181项 + 新增36项生命周期行为测试）。覆盖跨四个月和超过三年的约束、共同生效未知/不相交、原文页绑定、同事件不同机制、来源撤销/修订重审、预算溢出、幂等导入、事务中断回滚、版本切换/回退、现场事实与人工结果保留、损坏/不兼容/内部字段拒绝、错误目标联网前拒绝、发布签收过期、历史消息禁止和按月失败重试。

用旧冻结报告的814条事件进行真实数据流程试验：

- 显式导入 runtime/trial，保留未验收状态；原状态库和 normalized 文件的 SHA-256 与操作前完全相同。
- 旧状态库一致性备份及旧 normalized 副本保存在 runtime/trial/legacy-backup；原文和旧报告继续原位保留。
- 重评前后全部814条事实指纹相同。重评使用未配置环境，因此814条内部相关度/处置优先级和510条告警等级发生评估调整；这不是微软来源发生814次变化，也不是事故已确认。
- 生成独立 `.changes.json`、HTML 与候选 gzip 包。HTML保留814张事件卡片，没有模板占位符遗漏，显示 trial 和跨期覆盖缺口。
- 真实候选包未验收、未导入 production。包有814条公开事件、0条经审阅约束、0条组合风险；这说明历史语义建设尚未开始，不能把文件导出成功当成跨期覆盖已完成。

产物入口：`runtime/trial/reports/latest.html`；候选包 `runtime/trial/packages/windows-month-smoke-0.0.3-candidate.json.gz`；差异文件见对应 reprocess 报告。所有试跑产物保持 Git 忽略。

## 下一步预发布动作

1. 先选最近一季度，按月运行并逐来源核对历史入口与缺口。已知事故可作为验收案例，但缺当时原文快照时不能计算提前量。
2. 从真实原文提取少量长期约束，评审跨期候选，补至少几类不同机制的可追溯组合判断；同时保留排除和未知情况。
3. 验收首版公共包，演练空空间恢复、新版切换和回退，完成自由文本隐私与引用条件检查。此时再上传用户授权的 GitHub 数据版本。
4. 情报负责人、测试协调人各一名（可兼职），先人工审阅分享一份试点报告，再按周试4–6期。跨期风险先人工分享，暂不启用无人值守自动群发。
5. 用误报/遗漏、操作可执行性、实际核验结果和人工耗时决定转月报；三年剩余数据和历史来源完善并行，不作为首次试点的等待门槛。

可执行命令和字段契约见 [预发布操作指南](../skills/windows-os-intelligence/references/pre-release-operations.md)。清单未打勾项保留，避免把首轮实现误称为全部 P0 已完成。
