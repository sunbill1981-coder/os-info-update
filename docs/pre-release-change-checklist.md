# Windows 外部风险 Skill：修改清单与预发布行动

制定日期：2026-10-08。状态：首轮代码实施及本地验收已完成；详见 [实施验收记录](pre-release-implementation.md)。未勾选项仍待完成，不表示已授权群发、上传数据。

目标是持续捕获 Windows 外部变化及生态问题，尽早发现云桌面的潜在风险。内部产品资料作为可选增强，缺失时保留内部适用性未知。生产机制使用通用维度和配置，具体事件、KB、SID、TPM 等案例只作为证据数据与验收样例。

## 改动前的能力与边界（清单制定时）

可复用：稳定事件标识、事实与评估指纹、事件变化历史、来源证据与核验记录、外部风险分诊、结构化核验行动、离线 HTML、显式开启的飞书群告警。

清单制定时的缺口：历史关联主要按相同关联键和最近 30 天 last_seen 检索，重点用于多源佐证；尚无跨期组合风险记录。报告会过滤窗口外事件。采集用途和数据验收状态没有分离，同一工作空间的试跑会写状态库、检查点和最新报告。三年完整覆盖、正式数据包导入、历史重处理与版本切换也尚未形成完整流程。

既有测试通过结果可作为后续回归基础，不能作为新增能力的验收证明。既有未标记数据按“未分类”处理，不能自动认定为正式基线。

## 修改清单

复核说明：勾选仅表示对应实现和本地验收已具备；真实来源覆盖、公开内容审阅和试点验收仍需执行。复合条目只实现部分时保持未勾选，现有能力与边界以实施验收记录为准。

P0 表示首次小范围群发前应具备的最小能力。P1 可以在试水期间完善；不以三年全部回填完成作为首次试水门槛。

### C1 · P0：运行用途与存储隔离

- [x] 新增 `run_purpose=debug|trial|production`，与现有 backfill/rolling/incremental 模式独立；未指定时默认 trial；调度任务通过 --purpose 明确用途，不自动继承上次用途。
- [x] 为不同用途隔离状态库、采集检查点、normalized 数据、报告和发布记录。当前各用途独立缓存；未来可以设计只读共享，不能共享可写业务状态。
- [x] 运行清单和报告显著显示用途、空间、来源覆盖与失败情况；防止用途与实际空间不一致。
- [x] 现有工作空间先备份并保留为未分类存量；通过显式导入建立新空间，不自动将存量升级为 production。

验收：在 trial 重跑、回填旧月份或中断失败后，production 的事件、检查点、最新报告及告警记录均不变。debug 的合成数据不能通过普通导出进入正式历史基线。

### C2 · P0：有效行为与约束记录

- [x] 在原始事件之外维护约束记录：关联事件及修订、组件/流程、变化前后行为、必要条件、产品/版本范围、排除边界、证据；缺失信息以unknown状态、未提取范围及review_note明确说明。
- [x] 分开记录来源公布/修订时间、抓取时间和来源明确的生效时间；生效时间不明时保持未知。
- [x] 支持仍有效、被替代/撤销、有效性未知等状态和依据。时间久远不是失效依据；某条故障已修复也不能自动删除相关长期前提。
- [x] 为约束建立稳定标识；文字和范围修订产生新修订，不制造另一个重复约束。

验收：仅有标题或 KB 时不能补出行为约束；来源未说明的配置和命令不得生成。范围与修订可回查到原文，内部限制不混入公共 Windows 事实。

### C3 · P0：跨期检索与组合风险跟踪

- [ ] 新变化到来时，按机制/组件、工作流、前提、依赖关系和版本范围检索历史候选；仍有效或有效性未知的重要约束不受固定 30 天淘汰。
- [x] 区分“同一风险的多源佐证”与“多个不同变化可能共同产生风险”。共享组件或 KB 只能帮助召回，不能直接确认组合风险。
- [x] 对候选说明共同生效条件、作用路径、支持/反驳证据和未知项。明确不相交的范围排除；范围未知不能自动认定不相交。
- [x] 保存独立风险跟踪记录及修订：稳定风险标识、原始事件/约束修订、当前假设、外部证据状态、内部适用性、下一步、复查触发条件。
- [x] 使用有预算的候选检索和智能体审阅，不对全部历史事件无限两两组合；检索截断和未完成评审必须显式留作缺口。
- [x] 首期允许人工/智能体提交可追溯的关联评审记录，确定性脚本负责校验、持久化和报告；不宣称现有采集脚本能自动理解所有机制联系。

验收：跨四个月的 A+B 可形成同一条待验证风险；版本明确不相交时不强行联动；仅同组件、仅同 KB、转载增加时不升级成已确认风险。重复运行不重复建线程；后续证据更新同一线程。

### C4 · P0：跨期报告与语义变化清单

- [x] 报告分别展示本期来源变化、本期重评的历史风险、仍需跟进的重点风险。
- [x] 每条持续风险显示上次结论、本次变化、下一步、负责人/建议角色及稳定风险标识，支持展开证据时间线。
- [x] 将风险记录作为独立报告对象，避免被窗口事件过滤删除；历史背景不计作本期新增事实。
- [ ] 对范围、组合关系、结论和核验建议的实质变化生成差异；分开记录纯评分、措辞或格式变化。
- [x] 延续可配置阅读预算和高关注溢出入口；明确待评审积压和覆盖缺口。首页条数不作为安全结论或完整评审证明。

验收：5 月的报告能展示对 1 月事件的新风险认识，但不会把 1 月公告改成 5 月发布。窗口内来源事实没有变化时，跨期风险仍能按其进展入选。

### C5 · P0：数据验收、公共导出与基线导入

- [x] 区分候选与已验收数据。通过有校验记录的晋升流程生成正式数据包，不能仅修改 `approved` flag 绕过验收。
- [x] 包清单包含 dataset_id/version、格式版本、skill/code 版本、规则版本、来源与时间范围、缺口、输入运行、文件校验值和验收说明。
- [x] 公共导出使用字段白名单：公开事实、来源引用和明确标识的推演。排除独立内部画像/现场匹配、知识库回答、私有反馈和运行发布状态等字段；自由文本的客户信息、私有备注与凭据仍须验收者逐项检查。
- [ ] 大型数据包与 skill 代码分开版本管理；完整原文快照存于受控证据存储，公开包保留来源与指纹，并记录各来源的使用条件。
- [x] 基线导入验证兼容性与校验值，按稳定标识/修订幂等合并；预览新增、更新、冲突和忽略记录；不得覆盖本地测试结果、配置或凭据。
- [x] 历史导入不冒充实时采集，不推进实时来源检查点，不补发历史告警。

验收：空 trial 空间可恢复基线，重复导入没有重复事件/线程；损坏或不兼容包不部分激活；公开包无内部内容。数据允许带明确覆盖缺口被验收，验收并不代表全网完整或所有风险已确认。

### C6 · P0：历史重处理与正式版本更新

- [x] 区分来源修订、解析/评估/关联升级和数据格式迁移，记录受影响处理阶段及版本。
- [ ] 最小重处理入口支持指定数据版本和范围，在隔离空间使用已有证据生成候选新版；不覆盖已发布快照。
- [ ] 输出事实、范围、关联、结论和行动变化清单，标明需复核条目。纯报告样式改变不要求重抓三年数据。
- [x] 证据不足时列明无法重处理项；新抓取的现有页面注明当前抓取时间，不冒充当时快照。旧版模型解释也不能作为新版的来源事实。
- [x] 人工反馈和测试结果独立保存，关联事件/风险及其修订和基线。新推演有冲突时要求复核，不能覆盖过去实际执行的结果。
- [x] 通过验收后切换活动数据版本，支持固定版本和回退。重处理本身不发送群消息；重要语义变化进入发布候选。

验收：v0.1 可保留、v0.2 可验收切换并回退；相同来源事实保持身份；关联规则升级能产生新评估而不伪造新事实；过去人工测试记录仍可追溯。

### C7 · P0：历史回填批处理与覆盖台账

- [ ] 用按月可恢复批次执行回填，记录每个“月份×来源”的状态、数量、失败、未覆盖和待核验内容；只重试失败/缺口批次。
- [ ] 先核对目标版本的历史页面和可获取档案，补正式版本/KB说明、安全加固与前提变化等来源。不得把重复读取当前页面或近期订阅称作完整三年历史。
- [x] 索引发现、正文获取和范围核验分别计数；未读正文的预览条目不作为已核实约束。
- [x] 历史重建按“当前可获得历史”标记。提前预警验收仅使用各时点真实可获得的证据，缺快照时不计算提前量。
- [ ] 回填覆盖与定期新变化监测使用独立任务状态；处理中断不破坏生产增量检查点。

验收：季度样板能单独恢复失败月；报告明确来源缺口、旧公告的当前修订状态和语义核验积压。过去三年月份跑完不能单独触发“完整覆盖”声明。

### C8 · P0：试点与正式发布边界

- [x] 增加发布目标 none/pilot/formal，与运行用途、数据验收、采集模式分别配置。
- [x] debug 禁止外发；trial 仅允许配置的试点目标；production 向正式目标发布仍显式开启。无法验证目标时停止外发，保留本地结果。
- [ ] 发布前预览消息、目标、依据版本和事件/风险修订；基线同步与消息推送分开执行。
- [ ] 延续可恢复的发送状态和幂等机制；重要风险语义变化使用可追溯的发布版本/指纹，评分或措辞变化不重复发消息。
- [ ] 失败源和未核验假设在试点消息中明确展示；群发内容保持公开证据、潜在关联和内部验证结论的区分。

验收：历史导入、重处理、debug、错误目标均不产生群消息；重复发布不重复提醒；同一风险出现重要新证据可以进入新消息候选。真实群发送需在用户授权的目标和范围内执行。

### C9 · P0：最小反馈闭环

- [x] 建立私有、可导出的反馈记录，关联稳定事件/风险标识及报告/修订版本。
- [x] 最小字段：适用/不适用/未知、操作是否清楚、证据缺口、是否执行及结果、实际测试基线、负责人、下一步和更新时间。
- [x] 未分派与未执行保持明确；“未复现”不能自动关闭所有版本风险。
- [x] 每期加载上期未完成事项，避免依赖聊天记忆。反馈可能影响内部判断，但不能改写外部来源事实或自动进入公开数据包。

验收：从上一期到下一期能保持同一核验事项；来源修订后可指出需要重审的旧结论；不需要先建设复杂飞书应用即可试点。

### C10 · P0：Skill 指导、迁移与发布验收

- [x] SKILL.md 简要路由运行用途、跨期评审、数据导入/重处理和发布；详细契约放支持文档，减少重复说明。
- [x] 配套更新 CLI 帮助、README、事件模型、发现指南、HTML模板和发布指南；未实现的参数不得写成可执行命令。
- [x] SQLite 变更采用备份、迁移预览和幂等迁移；保持现有事件身份、事实指纹及审计历史，派生对象独立版本化。
- [x] 增加下面的行为验收集并执行已有回归；具体事故只作为验收数据，不变成生产特权规则。

首期行为验收集：

| 场景 | 必须观察到的结果 |
|---|---|
| 跨月 A+B、有机制依据且条件可能相交 | 建立待验证组合风险，引用两个来源修订 |
| A+B 版本明确不相交 | 不确认组合；保留排除依据 |
| 版本或共同生效条件未知 | 记录待补证，不能当作安全或已受影响 |
| 同组件、同 KB、转载或同作者重复 | 不自动合并事件、不提升独立佐证 |
| 旧约束被明确撤销或替代 | 更新适用状态，并重审依赖它的风险 |
| 超过三年的仍有效约束 | 仍可进入相关检索 |
| 窗口外风险在本期有实质新认识 | 报告显示进展，历史事实日期不变 |
| 导入两次同一基线或重复重处理 | 身份稳定，无重复数据或消息 |
| trial/debug 回填、失败或中断 | production 状态及发布记录不变 |
| 数据包损坏、格式不兼容或含内部字段 | 阻止激活/公共导出并报告原因 |
| 新版规则改变分析 | 生成候选差异，已发布快照及人工结果保留 |
| 证据来自后来修订页面 | 不声称当时可提前预警 |
| 发布目标不符、历史导入或重处理 | 不群发 |
| 高关注超展示预算、检索截断或来源失败 | 显式显示积压/缺口，不暗示已全部评审 |

## 预发布行动安排

### 阶段 A：本地准备与季度样板

先执行修改清单的 P0，不先全量回填三年。固定一个 skill/code 候选版本和 trial 运行配置。用三个完整月份分月回填，再准备机制不同的跨期样例；真实当时证据不足的案例仅用于今天的分析能力验收。

完成候选数据包导出、空空间恢复、重复导入、重处理差异和回退。可以逐步增加真实资料，但样例或不完整数据不能被默认为正式历史。

### 阶段 B：建立首版历史基线

优先整理最近 12 个完整月份和必要的更早约束/验收案例，通过验收后生成历史基线 v0.1。以 2026-10-08 为参考，最近 12 个完整月份为 2025-10 至 2026-09；三年完整月份口径为 2023-10 至 2026-09，2026-10 另做增量。

数据包应准确声明缺口。三年其余月份可持续补齐，不以数据条数或月份任务全部成功作为风险发现质量证明。GitHub 导出只选公共包；公开仓库中的数据可被访问，即使未向群推送。先本地形成可审阅包，再执行用户授权的上传。

### 阶段 C：首次试点发布

最小人员配置为一名情报/发布负责人、一名测试协调人，可兼职；按风险找相应组件工程师参与。

选少量熟悉产品的研发、测试和支持人员作为试点读者。首期人工核对全部高关注项、已展示与未展开候选、跨期新判断和覆盖缺口。预览消息后向授权试点目标发送一次，验证入口、内容、幂等与反馈链路；先不启用无人值守全自动群发。

### 阶段 D：每周试水

建议先试水 4–6 周，此为可调整建议，不是已经安排的日程。保持近期监测，按周汇总少量需要关注或行动的变化，并带上持续风险进展。没有新行动事项时简短说明，不能重复推送整批存量。

每期记录：反馈条目数、适用/不适用/未知原因、行动可执行性、实际核验结果、人工耗时、遗漏及跨期关联是否有用。证据不足与无人执行分别统计；不以点赞数代替风险发现效果。

### 阶段 E：转为正式发布

转正条件以行为为准：运行隔离和版本恢复可靠、无历史告警洪水、重要风险没有因预算静默消失、工程师能执行首步、反馈能跨期延续、人工工作量可承担。

正式阶段采用持续采集与评审、月度汇总，高优先级实质变化经确认后及时提醒。月报是发布节奏，不是等待新风险被发现的周期。数据继续按新来源事实或 skill 能力更新发布新版，旧发布快照保持可回溯。
