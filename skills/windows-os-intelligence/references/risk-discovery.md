# 通用风险发现与预警

本流程用于发现尚未进入结构化官方源的 Windows 风险。它不是特定事故的关键词清单。

## 发现对象

围绕新版本、构建号、KB、驱动或组件，寻找以下变化：安全机制收紧、默认行为改变、新前置条件、弃用或移除、版本组合限制、部署方式限制、更新回归，以及原有技术债被新行为暴露。

## 发现步骤

1. 从确定性采集结果提取新 KB、构建号、组件、错误码和受影响产品。
2. 优先查询 Microsoft Support、Microsoft Learn Troubleshoot、Windows IT Pro、产品专项发布说明和厂商公告。
3. 对尚无官方说明的异常，再查询 Microsoft Q&A、厂商论坛、GitHub Issue 和可信技术社区。
4. 每个网页保存为独立证据，不把搜索摘要当作完整证据。记录发布日期、抓取时间和规范 URL。
5. 提取变化、触发条件、前置条件、影响流程、症状、临时缓解和永久解决方案。缺失字段保持未知。
6. 只有事件语义一致时才写入同一 `correlation_keys`；共享 KB 或产品版本本身不足以合并。
7. 将候选记录写入 `data/inbox/signals.ndjson`，再由确定性评估器打分、去重和保存历史。

每行至少包含标题、规范来源 URL、来源等级、时间、产品、原文证据和置信度。已由研究过程确认的结构化维度可以直接提供，但不得猜测：

```json
{"title":"官方或社区原始标题","source_url":"https://example.invalid/advisory","source_id":"external-signal","source_tier":"P1","published_at":"2026-08-20","products":["Windows 11, version 24H2"],"roles":["guest"],"components":["authentication"],"identifiers":{"kb":["KB5000000"]},"summary":"来源摘要","evidence":"支持判断的原文证据","confidence":80,"correlation_keys":["语义一致时由研究过程生成的风险指纹"]}
```

## 查询构造

查询应由本轮出现的实体动态生成。组合 KB/Build/组件与通用风险意图，例如：已知问题、回归、兼容性、安装后失败、不再支持、新要求、临时解决方案、企业环境、虚拟机、宿主机/来宾机不一致。不要为单个历史事故固化查询。

## 告警状态

- `正式告警`：技术风险和环境相关度高，且有高置信度权威证据。
- `调查预警`：技术风险和环境相关度高，置信度中等，且至少有两个独立来源佐证。
- `重点关注`：处置优先级较高，但尚未达到告警门槛。
- `持续观察`：相关但当前影响或证据有限。
- `留档`：低相关或低影响信息。

低置信度不等于低风险。它决定是否能宣称“已确认”，而不是决定是否值得立即验证。
